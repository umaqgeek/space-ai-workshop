01 / HOW THE COMPONENTS CONNECTSystem architecture

          
Download SVG ↓

          
One browser app and a shared Python backend. Serve it locally or on Heroku; connect a model only when AI generation is needed.

          
          
Prepared knowledge base
The generator creates JSON, CSV and GeoJSON. The backend loads the JSON records into memory at startup; changes require an app restart or redeployment.
Model connection
The Python backend calls the configured Ollama-compatible service. Local Ollama works for local development; Heroku needs a reachable hosted endpoint. Model credentials stay on the backend.
Retrieval approach
This implementation uses lexical BM25 ranking with place and topic constraints. It does not train a model, generate embeddings or use a vector database.
Explore BM25: scoring and its variables ↗
Read the Stanford information retrieval chapter ↗

          
What does BM25 do in this project?
BM25 ranks records by how well their words match your question. It weighs how distinctive a word is across the candidate records, limits the benefit of repeating it, and adjusts for record length. A higher score means a stronger text match, not greater factual confidence.
Here, place and topic filters narrow the candidate records first. The code then uses k1 = 1.5 and b = 0.75 and returns the top matches. BM25 is the search step; the LLM is the optional writing step.

          

        

        

          
02 / FROM QUESTION TO RESPONSEProcess flow

          
Download SVG ↓

          
Trace the actual request path, including validation errors, insufficient evidence and model fallback.

          
          
Evidence before generation
No matching sources, or a request for live conditions or predictions, produces an insufficient-evidence response without calling the model.
Transparent fallback
Model errors, timeout errors, empty answers or failed citation checks use retrieved excerpts instead. The response reports the actual mode and includes a notice.
Human verification
Citation checks validate source IDs, not factual entailment. A person still needs to compare each claim with the source record, date, value and limitations.

          

        

        

          
03 / NO CODING KNOWLEDGE NEEDEDFrom your question to a grounded answer

          
Download SVG ↓

          
Think of the assistant as a team: a front desk receives your question, a researcher finds evidence, and a writer helps explain it.

          
          
RAG = find, then explain
Retrieval-augmented generation means finding relevant reference material and giving it to an AI model to help write an answer. The model is not being trained on your question.
Ollama and the model
Ollama provides access to the model. Gemma or Qwen is the LLM that produces the words, depending on the model configured and available on your endpoint.
Offline has limits
Offline mode retrieves and displays source excerpts. It does not generate a new explanation with an LLM. Neither mode can fill gaps in the synthetic dataset with verified facts.
