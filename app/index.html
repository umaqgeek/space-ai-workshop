01 / HOW THE COMPONENTS CONNECT
System architecture
Download SVG ↓

          
One browser app and a shared Python backend. Serve it locally or on Heroku; connect a model only when AI generation is needed.

          
          
Prepared knowledge base
The generator creates JSON, CSV and GeoJSON. The backend loads the JSON records into memory at startup; changes require an app restart or redeployment.
Model connection
The Python backend calls the configured Ollama-compatible service. Local Ollama works for local development; Heroku needs a reachable hosted endpoint. Model credentials stay on the backend.
Retrieval approach
This implementation uses lexical BM25 ranking with place and topic constraints. It does not train a model, generate embeddings or use a vector database.

        

        

          
02 / FROM QUESTION TO RESPONSE
Process flow
Download SVG ↓

          
Trace the actual request path, including validation errors, insufficient evidence and model fallback.

          
          
Evidence before generation
No matching sources, or a request for live conditions or predictions, produces an insufficient-evidence response without calling the model.
Transparent fallback
Model errors, timeout errors, empty answers or failed citation checks use retrieved excerpts instead. The response reports the actual mode and includes a notice.
Human verification
Citation checks validate source IDs, not factual entailment. A person still needs to compare each claim with the source record, date, value and limitations.
